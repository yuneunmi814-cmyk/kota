## 문서 간 원칙

| 원칙 | 내용 |
|---|---|
| **레포 우선** | 문서와 레포 실제 상태가 다르면 **레포가 옳다.** 단, 다르다는 사실은 CTO가 먼저 알린다 |
| **단일 출처** | 같은 내용을 두 문서에 쓰지 않는다. 공모전 일정·배점 = COO §10 / 기술 현황 = CTO / 타겟·메시지 = CMO |
| **미확인 표기** | 확인하지 못한 것은 추측으로 채우지 않고 `미확인`이라고 쓴다 |
| **대안 기록** | 결정에는 **검토했다 버린 대안**을 함께 남긴다 (COO §9-1, CTO ADR) |

## 갱신 규칙

- **push는 CTO 전담** (08-03 결정). COO·CMO는 문서를 CTO에게 전달하고 CTO가 올린다
- 기능이 추가·숨김될 때 CTO가 [`03_제품_기능_현황.md`](02_CTO_윤은미/03_제품_기능_현황.md)를 갱신한다
- 기술 결정을 내릴 때 CTO가 [`06_기술_의사결정_기록.md`](02_CTO_윤은미/06_기술_의사결정_기록.md)에 ADR을 추가한다
- 월 1회 전원이 문서 세트 상호 정합성을 대조한다 (COO §5-4)
