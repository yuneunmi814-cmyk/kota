# 자동화 설계 — 미팅 자료 → 정보 추출 → 축적

> CMO 요청(08-03): *"미팅 자료를 어떤 기반으로 전략을 추출하고 어떤 정보를 가지고 갈지 **기준을 설정**해서, 어떤 자료를 어디다 자동화할지 **설계**해 달라."*
>
> **작성** · 최용우(COO) · **일자** · 2026-08-03

---

# 1. 문제 정의

미팅 1회는 30분짜리 녹취 텍스트를 남긴다. 그 안에는 **성격이 전혀 다른 정보가 섞여 있다.**

- 3주 뒤에 찾아볼 것 (결정)
- 오늘 누가 해야 할 것 (액션)
- 개발 큐에 들어갈 것 (이슈)
- 전략 문서를 고쳐야 한다는 신호 (시그널)
- 그냥 버릴 것 (잡담·중복)

**이걸 한 덩어리로 저장하면 아무도 안 읽는다.** 지금까지 액션아이템 추적률이 0%였던 이유가 이것이다 — 회의록은 있었지만 *꺼내 쓸 형태*가 아니었다.

> 따라서 자동화의 핵심은 "요약"이 아니라 **분해(decomposition)** 다.

# 2. 추출 기준 — 미팅 1회 → 5종 산출물

| # | 종류 | 정의 | 소비자 | 목적지 |
|---|---|---|---|---|
| ① | **결정** | 확정된 사항. *"~하기로 함"* | **3주 뒤의 우리** | 시트 `회의록` (구분=결정) |
| ② | **액션** | 담당자가 붙은 할 일 | **담당자 (오늘)** | 시트 `팀_할일` |
| ③ | **이슈** | 제품 결함·리스크 | **CTO (개발 큐)** | 시트 `회의록`(구분=이슈) + 심각 시 GitHub Issue |
| ④ | **시그널** | 타겟·수익모델·포지셔닝·범위 관련 언급 | **문서 정합성** | 전략 문서 갱신 트리거 |
| ⑤ | **전문** | 정리된 회의록 전체 | **AI·검색** | GitHub `docs/` (CTO push) |

## 2-1. 판별 기준 (프롬프트에 그대로 넣는다)

| 종류 | 판별 신호 | 필수 필드 |
|---|---|---|
| 결정 | "~하기로", "확정", "그렇게 가자" | 안건 / 선택 / **사유** / **검토한 대안** / 담당 |
| 액션 | "~해주세요", "제가 할게요", "~까지" | 담당 / 할 일 / 기한(없으면 `(기한 미정)`) |
| 이슈 | "안 돼요", "없어요", "이상해요" | 현상 / 영향 범위 / 재현 조건 |
| 시그널 | 타겟·수익·이름·범위·경쟁 언급 | 발언 요지 / 기존 문서와 충돌 여부 |

## 2-2. 버리는 것 ★

**버리는 기준을 명시하지 않으면 자동화는 쓰레기를 그대로 옮긴다.**

- 잡담·인사·근황
- **개인사** (건강·가족·이직 등) — 팀 기록에 남길 사안이 아니다
- **자책·감정 발언** — *"내가 게을러서"* 류. 원인 규명에 필요하면 사실만 남기고 감정은 뺀다
- 같은 말의 반복, 결론 없이 흐지부지된 논의
- 타 프로젝트 상세 (단, **일정·리소스가 겹치면 `공유`로 한 줄만**)

> 실제 적용 예 — 08-03 회의에서 7월 정체의 원인이 개인 경조사로 언급됐다.
> **운영상 필요한 사실("7월 초 이후 진도 정체")만 남기고 개인사는 제외**했다.

# 3. 파이프라인

```
[회의] CTO 녹음 (클로바노트)
   │
   ▼  자동 텍스트 변환
[녹취 텍스트] ──→ COO 전달
   │
   ▼  ① 고정 프롬프트로 5종 분해        (Claude)
[결정] [액션] [이슈] [시그널] [전문]
   │
   ▼  ② 검수 — COO 30초 확인          ★ 자동화 안 함
   │
   ▼  ③ 배포
   ├─→ 시트 `회의록` 탭      (결정·이슈·공유)
   ├─→ 시트 `팀_할일` 탭     (액션)
   ├─→ GitHub `docs/`        (전문) ※ push는 CTO
   └─→ 시그널 → 전략 문서 갱신 필요 알림
```

## 3-1. ②검수를 자동화하지 않는 이유 ★

**LLM은 없는 내용을 지어낸다.** 회의록은 히스토리 자산인데, 지어낸 결정이 하나 섞이면 자산이 아니라 **부채**가 된다. 3주 뒤 그걸 근거로 판단하게 되기 때문이다.

검수는 30초면 된다. 확인 항목 3개:

- [ ] **결정 항목이 실제로 회의에서 확정된 것인가** (논의 중인 걸 결정으로 올리지 않았나)
- [ ] **담당자가 실제 발언자와 맞는가**
- [ ] **없는 기한을 만들어내지 않았나**

> 나머지는 전부 자동화한다. **사람이 남는 지점은 "판단"이지 "옮기기"가 아니다.**

# 4. 자동화 단계 (현실적 로드맵)

| Phase | 상태 | 내용 | 사람이 하는 일 |
|---|---|---|---|
| **0** | ✅ 현재 | 고정 프롬프트로 분해 → 수동 붙여넣기 | 전달·검수·붙여넣기 |
| **1** | 다음 | 프롬프트 출력을 **시트 붙여넣기 형식(TSV)** 으로 강제 | 전달·검수·붙여넣기 1회 |
| **2** | 8월 중 | **Gemini 시트 연동**으로 붙여넣기 제거 | 전달·검수 |
| **3** | 검토 | Apps Script 트리거 / GitHub Actions | 검수만 |

> **Phase를 건너뛰지 않는다.** 0단계가 안 돌면 3단계도 안 돈다.
> n8n 등 별도 인프라는 자동화 대상이 5개를 넘을 때 재검토한다 (현재 2개).

# 5. 데일리 리포트

미팅이 주 3회이므로 실질적으로 **"회의 직전 리포트"** 다. 목적은 하나 — **회의에서 현황 파악에 쓰는 시간을 0으로 만드는 것.**

## 5-1. 양식

```
📊 현황 (MM/DD)
🔴 막힘 N건 — <누가 무엇에>
⏰ 기한 지남 N건
✅ 완료 N건 (지난 회의 이후)
🔧 커밋 N건 — <주요 변경>
👉 다음 우선순위 3개
```

## 5-2. 데이터 출처 — 전부 자동 집계 가능

| 항목 | 출처 | 방법 |
|---|---|---|
| 막힘 / 기한지남 / 완료 | 시트 `팀_할일` | `COUNTIF` 수식 (사람 개입 0) |
| 커밋 | `git log --since=<지난 회의>` | 명령 1줄 |
| 우선순위 3개 | — | **COO 판단** (자동화 안 함) |

> 5개 중 4개가 이미 자동이다. **판단만 사람이 한다.**

## 5-3. 시트 수식 (`대시보드` 탭)

```
막힘      =COUNTIF(팀_할일!C:C,"1-막힘")
진행      =COUNTIF(팀_할일!C:C,"2-진행")
대기      =COUNTIF(팀_할일!C:C,"3-대기")
완료      =COUNTIF(팀_할일!C:C,"4-완료")
기한지남  =COUNTIFS(팀_할일!F:F,"<"&TODAY(),팀_할일!F:F,"<>",팀_할일!C:C,"<>4-완료")
완료율    =COUNTIF(팀_할일!C:C,"4-완료")/COUNTA(팀_할일!A2:A)
```

담당자별 진행률까지 붙이면 CMO가 요청한 **대시보드**가 된다.

# 이 문서를 작성하면서 발견한 개선점

**① 자동화의 본질은 요약이 아니라 분해다.**
"회의록 요약해줘"는 읽을거리 하나를 더 만들 뿐이다. 정보를 **소비자별로 쪼개서 각자의 자리로 보내야** 실제로 쓰인다. 액션아이템 추적률이 0%였던 건 기록이 없어서가 아니라 *꺼내 쓸 형태가 아니어서*였다.

**② 버리는 기준이 남기는 기준보다 중요하다.**
무엇을 남길지는 대개 명확하다. 문제는 무엇을 버릴지다. 이걸 정하지 않으면 자동화는 쓰레기를 빠르게 옮기는 기계가 된다. 특히 **개인사와 감정 발언**은 반드시 걸러야 한다 — 팀 기록은 나중에 외부에 공개될 수 있다.

**③ 검수는 자동화하지 않는다.**
LLM 환각이 히스토리에 섞이면 자산이 부채가 된다. 30초 검수를 남기는 것이 전체 자동화의 신뢰도를 지킨다.
