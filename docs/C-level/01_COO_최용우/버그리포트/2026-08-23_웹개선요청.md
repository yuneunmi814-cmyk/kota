# 🟠 BUG-01 [P1] 축제 데이터 중복 — 소스 간 ID 충돌

**증상**

`/ko/festivals/` **전체 539건을 빠짐없이 로드**해 (이름+기간) 기준으로 대조. tourapi·kfes 두 소스가 같은 `contentId`를 가진 축제를 별개로 취급해 **정확히 8쌍**이 중복 노출됨.

```
수원 국가유산야행 / 수원 국가유산 야행    tourapi-1916616 / kfes-1916616
동대문구 맥주축제                        kfes-3351268 / tourapi-3351268
명량대첩축제                             tourapi-607417 / kfes-607417
안흥찐빵축제                             tourapi-2027215 / kfes-2027215
금천시흥행궁문화제                       tourapi-4099989 / kfes-4099989
나주영산강축제                           kfes-3009344 / tourapi-3009344
자라섬재즈페스티벌                       stdfest-2026년재즈페스티벌in가평 / manual-jarasum-jazz-2026
김해분청도자기축제                       tourapi-506470 / kfes-506470
```

앞의 6쌍은 tourapi·kfes 두 소스가 같은 숫자 `contentId`를 갖는데도 URL 슬러그에 소스 접두사까지 포함돼 별개 축제로 취급됨. 마지막 1쌍(자라섬재즈페스티벌)은 소스가 `stdfest`/`manual`로 또 다른 조합 — 같은 병합 로직 결함이 소스 조합을 가리지 않고 발생함을 보여줌.

**영향** · 전체 539건 중 8쌍(16건)이 중복. 데이터활용 20점에 직접 영향.

**요청** · 병합 키를 `소스+contentId`가 아니라 `contentId` 단독으로 변경.

# 🟡 BUG-02 [P2] 전체 축제 목록 진입점 부재

**증상**

헤더에 로고·달력·언어뿐, 필터 없는 전체 목록(`/ko/festivals/`)으로 가는 링크가 없음.

```
헤더 링크    KOTA(로고) → /ko/ | 축제 달력 → /ko/calendar/ | 언어 선택
```

유일한 경로는 두 가지 — ① "지역으로 찾기" 섹션 **제목**이 링크로 걸려 있음(시각적 단서 없음) ② 검색어 없이 검색 버튼을 누르면 우회 진입됨(실측 확인).

**기대** · 헤더나 히어로에 명확한 전체 목록 링크

**요청** · 헤더에 `축제 전체` 링크 추가, 또는 히어로 아래 `전체 축제 둘러보기` 버튼

# 🟡 BUG-03 [P2] 홈 '내 주변 축제 보기' — 닫기 없음·상태 미저장

**증상**

버튼을 눌러 카드를 펼친 뒤 닫는 버튼이 없고(DOM 전체 검색 결과 0건), 새로고침하거나 다른 페이지에 갔다가 돌아오면 다시 접힘.

```
닫기/접기 버튼 검색       0개
localStorage 전체 키      kota_visitor 1개뿐 (펼침 상태 관련 키 없음)
sessionStorage 전체 키    0개
```

펼침 상태가 React 컴포넌트 메모리에만 있고 어디에도 저장되지 않아, 새로고침·페이지 이동은 항상 초기(접힘) 상태로 돌아감.

**요청** · 펼침 상태를 `sessionStorage`에 저장. 펼친 카드 옆에 접기 버튼 추가.

# 🟡 BUG-04 [P2] 테마 자동분류 정확도 — 7개 권역 전수조사, 최소 59건 미분류

**증상**

`/ko/festivals/?region=`으로 7개 권역 전체와 권역별 6개 테마(먹거리·꽃자연·역사전통·음악공연·가족체험·야경불빛) 필터 건수를 각각 대조. 권역 전체건수와 테마별 건수 합을 비교하면(테마 중복 태깅 시 합이 부풀려지므로 실제 미분류는 아래 수치 **이상**):

```
권역        전체    테마합   차이(최소 미분류)
서울         82      71      11
경기·인천    104     92      12
강원         23      19       4
충청         93      87       6
전라         75      60      15
경상        136     126      10
제주          5     (아래 참조) 1
────────────────────────────────
합계        518            최소 59건
```

제주 5건은 개별 대조까지 완료:

```
서귀포칠십리축제 (tourapi-506616)      꽃·자연 + 음악·공연 (2개 테마 중복)
제주올레걷기축제 (tourapi-1074568)     테마 0개 (미분류)
서귀포 원도심 문화페스티벌 (3512205)   테마 0개 (미분류)
새연교 주말 문화공연 (2434545)         음악·공연만
제5회 제주비엔날레 (3399432)           음악·공연만
```

'올레걷기축제'가 꽃·자연 테마 0개인 것은 명백한 오분류. 제주는 5건 중 2건(40%)이 어느 테마에도 안 걸림 — 다른 권역도 같은 패턴일 가능성이 높음(경상·전라는 미분류 비율이 특히 높음).

**요청** · 자동분류에 키워드 보정 추가(올레·둘레길·트레킹·트레일 → 꽃·자연 등). 제주 외 권역도 개별 축제 단위로 원인 확인 필요.

# 🟡 BUG-05 [P2] KOTA's Pick 캐러셀 자동 넘김 미작동

**증상**

```
버튼 라벨    "자동 넘김 멈추기"   ← 재생 중이라고 표시
t0   dots 24,6,6,6 (1번 활성)
t6s  dots 24,6,6,6 (변화 없음)
t12s dots 24,6,6,6 (변화 없음)

수동 도트 클릭    24,6,6,6 → 6,24,6,6  (정상 동작)
좌우 화살표       0개
```

버튼은 재생 중이라고 표시하지만 실제 타이머는 안 돎. 수동 클릭은 정상 동작 — 캐러셀 자체가 죽은 게 아니라 자동재생 타이머만 안 돎.

**요청** · 자동 넘김 타이머 복구, 또는 안 할 거면 버튼 라벨을 `자동 넘김 시작`으로 상태와 일치시키기. 좌우 화살표 추가.

# 🟠 BUG-06 [P1] 사진 뷰어 — 이전/다음 버튼 클릭 시 뷰어가 닫힘

**증상**

```
'다음 사진' 버튼 클릭   →  뷰어 닫힘 (다음 사진으로 안 넘어감)
'이전 사진' 버튼 클릭   →  뷰어 닫힘 (동일)

대조 — 키보드 → ← 방향키   →  정상 작동, 1/6 → 2/6 (별도 경로)
```

두 버튼 다 마찬가지. 키보드 방향키는 정상 작동하므로 넘기는 로직 자체는 있는데, 화면의 버튼에 클릭 핸들러가 안 걸려 있거나, 클릭 이벤트가 배경(닫기 담당) 쪽으로 새는 구조로 보임.

**영향** · 모바일은 키보드가 없으므로 탭으로는 사진을 절대 넘길 수 없음. 6장 중 1장만 보고 끝나는 구조.

> **참고** — 08-18 리포트에서 이 항목을 키보드 테스트만으로 "고쳐짐"으로 판정했으나 틀렸음. 실제 버튼 클릭 기준으로는 미해결.

**요청** · 화살표 버튼의 클릭 핸들러 재점검 — `onClick`이 실제로 다음/이전 인덱스 함수를 호출하는지, `stopPropagation()`이 빠져 배경 닫기 핸들러로 이벤트가 새는지 확인. 수정 후 키보드가 아니라 실제 클릭으로 재검증.

# 🟠 BUG-07 [P1] 상세 페이지 히어로 — 세로형 포스터가 72% 잘림

**증상**

```
원본 크기      443 x 627px (세로형, 비율 0.71)
히어로 표시    1112 x 440px (초광각, 비율 2.53)
object-fit     cover / object-position 50% 50% (정중앙 크롭)

가로 폭 맞추려 확대한 배율   2.51배
확대 후 세로 길이           1,574px
실제 보이는 세로 길이       440px
잘려나가는 비율             72% (위아래 각 36%씩)
```

영양고추 H.O.T 페스티벌(tourapi-1073801)·생생우리음악축제(tourapi-2853756) 두 사례 모두 완전히 같은 수치(443×627 → 1112×440)로 재현됨 — 개별 이미지 문제가 아니라 히어로 컨테이너 비율 자체의 구조적 문제. TourAPI 포스터 표준 규격으로 보여 이 소스를 쓰는 축제 전체에서 재현될 가능성이 큼.

**요청** · 세로형 원본은 `object-fit: contain`으로 전환하거나 히어로 컨테이너를 반응형으로. 최소한 `object-position`을 상단 우선(`50% 20%`)으로.

# 🟡 BUG-08 [P2] 모바일 필터 칩 — 대부분 화면 밖

**증상**

```
행1 (기간)  칩 17개 중 완전히 보이는 것  5개   숨은 비율 71%
행2 (권역)  칩  8개 중 완전히 보이는 것  4개   숨은 비율 50%
행3 (테마)  칩  7개 중 완전히 보이는 것  3개   숨은 비율 57%

scrollbar-width : none   (스크롤 가능하다는 단서 없음)
```

스크롤바를 숨겼는데 대체 단서(그라디언트 등)가 없어 더 있다는 걸 알 방법이 없음.

**요청** · 각 행 오른쪽에 페이드 그라디언트 추가, 또는 `필터` 버튼 + 바텀시트로 전환.

# 🟡 BUG-09 [P2] '방문객 순위' 배지 — 산정 기준이 화면에 안 보임

**증상**

```
화면에 보이는 텍스트   "경기 축제 59곳 중 방문객 11위"
기준 설명              <p title="지난 회차 방문객 실측 기준. 방문자 데이터가 있는 축제끼리 비교했어요.">
                       ← HTML title 속성 안에만 존재
안내 아이콘(ⓘ 등)      없음
```

`title` 속성은 마우스를 hover해야 뜨는 브라우저 네이티브 툴팁이라, **모바일(터치)에서는 이 설명을 볼 방법이 전혀 없음.** 시트 `Team_9` 메모는 기준을 "관광 빅데이터 기반 인기 프록시"로 적어놨는데 실제 코드 문구는 "지난 회차 방문객 실측"이라 표현이 다름.

**요청** · `title` 속성 대신 눈에 보이는 ⓘ 아이콘 + 탭 시 설명으로 전환. Team_9 메모를 실제 기준으로 갱신.

# 🟡 BUG-10 [P2] 모바일 — 목록에서 상세 진입 후 뒤로가기 시 스크롤 위치 유실

**증상**

모바일 뷰포트(390px)에서 실제 링크 클릭으로 재현:

```
더보기 10회 → 264장 로드, url ?page=11
클릭 직전    scrollY 31250
      ↓ 카드 클릭 → 상세 진입 → 뒤로가기
복귀 후      scrollY 3183   (31250 대비 90% 손실)
             카드 264개·url ?page=11 은 정상 유지됨
```

카드 개수와 URL은 정상 복원되는데 **스크롤 위치만 모바일에서 초기화됨.** 같은 시나리오를 PC(1280px)에서는 스크롤까지 정확히 복원되는 것을 확인함 — 모바일에서만 발생.

**요청** · 스크롤 복원 로직을 모바일 뷰포트에서 별도 점검. `history.scrollRestoration` 설정이나 프레임워크의 스크롤 복원 옵션이 모바일 브레이크포인트에서 꺼져 있지 않은지 확인.
