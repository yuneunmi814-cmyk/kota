# ADR-001 · 모노레포 · 독립 워크스페이스 4개

**상태** 유효 · **일자** 2026-06 (init)

- **결정** — 한 레포에 `backend/` `web/` `admin-web/` `mobile/` **독립 디렉토리 4개.** npm workspaces를 쓰지 않고 `package.json`·`package-lock.json`을 각각 유지.

- **비용** — 공통 타입(`api/types.ts`)이 web·mobile·admin-web에 **3중 복제**. 변경 시 수동 동기화
- **재검토 조건** — 타입 불일치로 버그가 2회 이상 발생하면

# ADR-002 · 백엔드는 빌드 없이 `tsx`로 직접 실행

**상태** 유효 · **일자** 2026-06

- **맥락** — `tsc` 빌드 산출물을 만들지, TS를 그대로 실행할지.
- **결정** — **`tsx`로 TS 직접 실행.** Dockerfile CMD = `prisma migrate deploy && npm run seed:prod && npm run start`. 빌드 단계 없음.
- **검토한 대안**
  - *`tsc` 빌드 후 `node dist/`* — 표준적이지만 배포 파이프라인에 단계가 하나 늘고, 3인 팀에서 빌드 캐시·소스맵 문제로 시간을 뺏길 위험
- **비용** — ① 기동 시 트랜스파일 오버헤드 ② **타입 오류가 런타임까지 살아남을 수 있음**
- **완화** — CI(`ci.yml`)에서 `typecheck`를 **별도 잡으로 강제**. 이게 없으면 이 결정은 성립하지 않는다
- **재검토 조건** — 콜드스타트가 심사에 문제가 되면 (현재 병목은 Render 슬립이지 트랜스파일이 아님)

# ADR-003 · 인프라는 Render **free 플랜** + keepalive cron

**상태** ⚠️ **수용된 부채** · **일자** 2026-07

- **맥락** — 수익이 0인 공모전 프로젝트. DB·Redis·API 서버가 필요.
- **결정** — Render **free 플랜 전부**(PostgreSQL·Redis·API·static) + GitHub Actions cron `*/5`로 `/health` 핑.
- **검토한 대안**
  - *유료 플랜* — 월 비용 발생. 수상 전까지 3인이 부담
  - *다른 무료 호스팅(Fly.io·Railway 등)* — 마이그레이션 비용 대비 이득 불확실
  - *서버리스* — Prisma·PostGIS 조합에서 콜드스타트가 더 나빠질 수 있음
- **비용** ★
  - 15분 무접속 시 슬립 → **약 50초 콜드스타트**
  - **free PostgreSQL 90일 만료** ← **가장 큰 리스크**
  - keepalive 워크플로 주석이 스스로 *"GitHub 예약은 지연될 수 있음"* 이라고 한계를 인정
- **완화** — 웹 3단 정적 폴백(ADR-008)이 사용자 눈에는 장애를 감춘다
- **재검토 조건** ★ — **S0-1에서 DB 만료일을 확인한 즉시.** 심사 기간(9~10월)에 걸리면 **무조건 유료 전환**한다

# ADR-005 · git **push는 CTO 전담**

**상태** 유효 · **일자** 2026-08-03 (팀 결정)

- **맥락** — 3인이 각자 push하면 충돌·되돌리기가 잦아진다. COO·CMO는 git 숙련도가 다르다.
- **결정** — **CTO만 push. COO·CMO는 pull만.** COO·CMO 문서는 CTO에게 전달해 CTO가 올린다.
- **검토한 대안**
  - *전원 push + 브랜치 보호* — 규칙 학습 비용. 3인 팀에서 PR 리뷰가 병목이 됨
  - *COO에게도 문서 디렉토리 push 허용* — 권한 분리 설정 비용 대비 이득 작음
- **비용** ★ — **단일 장애점이 생긴다.**
  - `05_품질_배포_보안.md` §7 확인 결과: 백엔드는 Render 웹 콘솔로 **누구나 롤백 가능**하지만, **웹 롤백은 git push가 필요해 CTO만 가능**하다
  - 즉 CTO가 못 움직이면 **웹 배포를 되돌릴 수 없다**
- **완화** — 배포·복구 절차를 문서화(S0-7). 최악의 경우 정적 폴백이 화면을 지킨다
- **재검토 조건** — CTO 부재로 롤백이 지연되는 사건이 1회라도 발생하면

# ADR-007 · 축제 데이터는 **2개 소스를 병행**한다

**상태** 유효 · **일자** 2026-08-03 (커밋 `9c343d8`)

- **맥락** — CTO가 실제로 영월·제천 축제에 갔는데 **코타에 그 축제가 없었다.** TourAPI 단독으로는 지역 축제 커버리지가 부족했다.
- **결정** — **TourAPI `searchFestival2` + 전국문화축제표준데이터** 2소스 통합. 결과 **121건 → 416건** (TourAPI 198 + STDFEST 218).
- **검토한 대안**
  - *TourAPI만 유지* — 커버리지 부족이 이미 실사용으로 확인됨
  - *지자체별 개별 API* — 소스가 수십 개로 늘어 유지 불가
  - *크롤링* — 법적·안정성 리스크
- **비용** ★ — **중복이 생긴다.** 고양호수예술축제가 `고양호수예술축제`(TourAPI)와 `2026 고양호수예술축제`(STDFEST)로 2건 들어와 있다. 이름이 완전히 같지 않아 단순 비교로는 안 잡힌다
- **미해결** — 통합 후에도 **제천 1건 · 영월 1건**. **원본 공공데이터에 2026년판이 아직 없기 때문**이며, 우리 코드 문제가 아니다. 그러나 사용자에겐 똑같이 "없는 서비스"다
- **후속** — S1-D2(중복 판정) · S1-D3(정기 sync)
- **재검토 조건** — 3번째 소스가 필요할 만큼 밀도가 안 나오면

# ADR-008 · 웹은 **3단 데이터 폴백**을 쓴다

**상태** 유효 (**의도치 않게 가장 중요한 결정이 됨**) · **일자** 2026-07-21 (커밋 `13aaaa1`)

- **맥락** — Render free 플랜 콜드스타트로 첫 진입이 느리거나 실패한다.
- **결정**
  ```
  ① 라이브 API (AbortSignal 6초 타임아웃)
        ↓ 실패
  ② public/data/*.json  (빌드 시 베이크 — 축제 416건 · 지역 23개)
        ↓ 없음
  ```

- **비용** — 정적 데이터가 오래되면 라이브와 어긋난다 → S1-D3 정기 sync가 `export:web`까지 함께 돌려 해소
- **⚠️ 구멍** — **`SearchPage`만 폴백을 안 쓴다.** 백엔드가 자면 검색만 통째로 실패 → S1-F1에서 함께 수정

- **★ 심사 활용** — *"결제·정산 인프라 구현 완료, 티케팅 확장 시 즉시 적용 가능"* → **발전성 20점 서술 근거**로 쓴다. 죽은 코드가 아니라 **준비된 확장점**이라는 프레임
- **재검토 조건** — 수익화 단계 진입 시

# ADR-013 · "AI 추천"은 **현재 규칙 기반 랭킹**이다

**상태** ⚠️ **재검토 예정 (08-04 안건)** · **일자** 기록 2026-08-04

- **맥락** — CMO 전략 문서가 "AI 개인화 추천"을 핵심 기능으로 서술한다. 코드에는 없다.
- **현재 구현 (실측)**
  - `recommendedCourses` = `saveCount desc` 정렬 (인기순)
  - `popularRegions` = DataLab 방문자수(`visitorScore`) 정렬
  - `trendingRegions` = 유튜브 조회수 로그 스케일(`buzzScore`) 정렬
  - "개인화"의 전부 = 로그인 사용자의 `UserInterest` 테마 ID로 섹션 필터링
  - **협업필터링·임베딩·벡터검색·행동로그 학습 전무.** 관련 의존성이 4개 `package.json` 어디에도 없음
- **실제로 있는 생성형 AI** — `modules/aicourse/from-video.ts`의 **Gemini 2.5 Flash**(영상 캡션 → 장소 추출 → 지오코딩 → DRAFT 코스). **모바일 전용, 웹에 없음.** 전용 테스트 0개
- **★ 결정이 필요한 것** — 셋 중 하나를 골라야 한다
  1. **웹에 AI를 넣는다** — 모바일 파이프라인 이식(3~5일) 또는 축제 추천 LLM 신규(5~7일)
  2. **문서에서 AI를 뺀다** — CMO 문서 수정. 대신 *"공공데이터 기반 규칙 랭킹"* 으로 정직하게 서술
  3. ~~그대로 둔다~~ — **심사에서 "기획서와 다른 서비스"로 감점.** 선택지가 아니다
- **기한 규칙** ★ — **8/23까지 결정이 없으면 자동으로 2안(문서 수정)으로 간주한다.** 미결정이 계속 살아 있는 것이 가장 나쁘다

# ADR-014 · 심사 제출물은 **웹 단독**으로 한다

# ADR-015 · 웹 제품 축은 **축제 단일**이다

**상태** ✅ **유효 — 2026-07-22 결정됨** (2026-08-04 발굴·기록) · **일자** 2026-07-22

- **맥락** — 문서 여러 곳이 제품을 *"축제 + 교통 + 식당 3축"* 으로 정의하는데, **웹에는 식당·교통 라우트가 없다.** 라우트는 `/` `/search`(숨김) `/festivals` 3개뿐이다.
- **★ 이미 결정되어 있었다** — `kota/CLAUDE.md`:
  > 홈 = "내 위치 기반 지역 축제" … **축제 단일 축(호텔·맛집 탭 없음, 결정 2026-07-22)**
- **그런데 이 결정이 CLAUDE.md 한 줄에만 존재했다.** COO 문서·CMO 문서·README에는 전달되지 않았고, 그 결과 COO는 식당·교통 QA를 준비했고 CMO 문서는 3축을 서술했다
- **결정** — **축제 단일 축 유지.** 식당·교통은 발전 계획으로 서술.
- **근거** (사후 검증)
  1. D-48에 3축을 다 만들면 **셋 다 얕아진다**
  2. 심사 배점 *완성도 30점*은 폭이 아니라 **깊이**를 본다
  3. 축제는 이미 **416건 데이터 · 2소스 파이프라인 · 위치 기반 필터 · 달력 API**까지 갖춰져 있어 **유일하게 "완성됐다"고 말할 수 있는 축**이다
- **연쇄 영향** — COO QA 체크리스트·CMO 문서·README를 이 결정에 맞춰 수정해야 한다 (S0-4·S0-5)
- **★ 규칙 신설** — **제품 범위 결정은 CLAUDE.md가 아니라 이 ADR 문서에 남긴다.** CLAUDE.md는 AI 코딩 컨텍스트이지 팀 합의 기록이 아니다. 팀이 읽지 않는 곳에 적힌 결정은 결정되지 않은 것과 같다
- **재검토 조건** — 공모전 이후 제품 확장 시

# 이 문서를 작성하면서 발견한 개선점

**① 결정의 "이유"는 반드시 결정과 같은 순간에 적어야 한다.**
7/22 검색 숨김이 증거다. 그때 30초만 더 써서 *"축제가 검색에 안 걸려서"* 를 남겼다면, 08-03의 재발견도 08-04의 코드 재독도 없었다. **이유를 나중에 복원하는 비용은 기록하는 비용의 수십 배다.**

**② 부채를 "수용된 부채"라고 부르니 관리가 됐다.**
ADR-003·011·012는 고치지 않기로 한 것이다. 그런데 **재검토 조건을 붙이니 방치가 아니라 결정이 됐다.** 모르고 방치한 것과 알고 미룬 것은 완전히 다르며, 후자만 관리할 수 있다.

**③ 의도하지 않은 이득도 기록해야 유지된다.**
ADR-008(3단 폴백)은 콜드스타트 대응으로 만들었는데 "백엔드가 죽어도 화면은 뜬다"는 훨씬 큰 안전망이 됐다. **기록하지 않았다면 다음 리팩터링에서 "불필요한 복잡도"로 지워졌을 것이다.**

**④ 미결정에 기한을 붙였다.**
ADR-013에 *"8/23까지 결정 없으면 자동으로 2안"* 을 넣었다. 3인 팀에서 가장 비싼 것은 잘못된 결정이 아니라 **결정되지 않은 채 살아 있는 안건**이다. COO의 48시간 묵시 승인(§6-1-④)과 같은 원리다.
