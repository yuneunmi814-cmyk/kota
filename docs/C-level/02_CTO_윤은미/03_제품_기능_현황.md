# 4. 🚨 가장 큰 괴리 — 식당·교통이 웹에 없다 ★

COO 문서 §2-1이 제품을 이렇게 정의한다.

> **제품** = 지방 축제 기반 여행팩 (**축제 + 교통 + 식당 3축**)

그리고 COO의 QA 루틴(§8-4)이 심사 데모 경로를 이렇게 잡았다.

> 첫 진입 → 축제(목록·상세·지도) → **식당(지역·카테고리·검색)** → **교통** → 로그인 → 모바일 → 외국어 → …

**그런데 `web/`에는 식당 라우트도 교통 라우트도 없다.** 라우트는 `/` `/search` `/festivals` 3개가 전부다.

| 축 | 웹 | 모바일 |
|---|---|---|
| 축제 | ✅ | ✅ |
| 식당 | ❌ **없음** | 스팟(관광지/식당) 형태로 부분 존재 |
| 교통 | ❌ **없음** | 지도 길찾기 버튼 |

## 4-1. ★ 사실 이미 결정되어 있었다 (2026-08-04 발견)

`kota/CLAUDE.md`의 `web/` 항목에 다음 문장이 있다.

> 홈 = "내 위치 기반 지역 축제" … **축제 단일 축(호텔·맛집 탭 없음, 결정 2026-07-22)**

**즉 7/22에 이미 "웹은 축제 단일 축"으로 결정됐고, 코드도 그렇게 되어 있다.**
문제는 그 결정이 **CLAUDE.md 한 줄에만 남았고 COO·CMO 문서·README에는 전달되지 않았다**는 것이다.

- 그래서 COO는 식당·교통 QA를 준비했고
- CMO 문서는 3축 제품을 서술했고
- 08-04에 CTO가 "미결정"이라고 잘못 적을 뻔했다

> **이건 미결정이 아니라 미전달이다.** 그리고 미전달은 미결정보다 나쁘다 — 아무도 다시 묻지 않기 때문이다.
> **08-04 안건은 "정하자"가 아니라 "이미 정해진 걸 문서에 반영하자"** 로 바뀐다.

## 4-2. 그래서 할 일

- COO QA 체크리스트에서 식당·교통·라인 로그인 제거 (S0-5)

# 이 문서를 작성하면서 발견한 개선점

**① 기능 목록이 없어서 우리가 뭘 만들었는지 아무도 몰랐다.**
COO는 "식당 탭 QA"를 계획했고, CMO 문서는 "AI 개인화 추천"을 핵심으로 썼고, README는 "라인 로그인"을 적었다. **셋 다 웹에 없다.** 이건 세 사람이 게을러서가 아니라 **기능 인벤토리라는 문서가 존재한 적이 없어서**다. 이 문서를 배포 때마다 갱신한다.

**② "숨긴 기능"은 반드시 이유와 함께 숨겨야 한다.**
7/22 검색 숨김은 커밋 한 줄로 끝났고, 그래서 08-03에 같은 문제를 다시 발견했고, 오늘 코드를 다시 읽어야 했다. **숨기는 비용은 1글자지만 잊는 비용은 2주다.** → ADR-004

**③ 제품 정의와 라우트 수가 이렇게 다를 수 있다는 게 놀라웠다.**
"축제+교통+식당 3축"이 문서 여러 곳에 반복돼 있는데 웹 라우트는 3개(그중 하나는 숨김)다. **반복해서 쓰면 사실이 된 것처럼 느껴진다.** 그래서 CTO 문서의 첫 번째 원칙을 *"문서가 코드보다 앞서 쓰이지 않는다"* 로 잡았다.
